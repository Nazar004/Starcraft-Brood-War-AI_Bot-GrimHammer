# Andromeda: пик Worker 120 мс

Источник: скриншот codex-clipboard-9c1a0261-ac00-438f-a40d-9f66570d0ed1.png.
Текущий кадр 22205, среднее 4,9 мс. Сохранённый максимум 249,3 мс.
На этом пиковом кадре самый дорогой модуль Worker — 120,0 мс, обработка отрядов — 25,0 мс. Оценка FAP около 0,1 мс, счётчик оценки боя 1. Новая карта расстояний одна, A* 0. Это не подтверждение повторения прежнего пика Combat 258,5 мс и не повторение массового создания 27 карт при проверке расширения.

120 мс Worker объясняют лишь часть 249,3 мс. Старый HUD показывает только один максимальный модуль и отдельные детали других этапов, поэтому оставшееся время нельзя приписать конкретному модулю по этому скриншоту.

В WorkerManager::update последовательно выполняются проверка статусов/угроз, перевозка SCV, освобождение блокирующих минералов, периодическое перераспределение, газ, idle, возврат груза, ремонт, минерал-локинг, разблокировка и посты. Подробного таймера этих фаз до изменения не было. В частности, статус рабочих вызывает поиск близкого слабого наземного врага и проверку опасности для каждого соответствующего SCV; ремонт содержит отдельные поиски работников, безопасной позиции и пути. Наличие этих циклов само по себе не доказывает источник 120 мс.

Добавлены измерения длительности каждой фазы и двух вложенных операций: findEnemyTargetForWorker и maybeFleeDanger. Счётчики сбрасываются перед каждым WorkerManager::update. Измерение опасности включает обработку ухода от угрозы и смену работы, а не только поиск врага. Вложенные времена входят в родительскую фазу и не должны прибавляться к ней.

GameCommander сохраняет фазу, длительность, вложенные времена и число запросов только вместе с новым глобальным максимумом кадра. HUD показывает строку worker, если максимальная фаза рабочих заняла не меньше 5 мс.

TimerManager теперь сохраняет четыре самых дорогих модуля того же пикового кадра, включая Other для остатка между измеренными модулями. Строка parts выводится вместе с peak и помогает объяснить время, которое не покрывает один Worker.

Порог/частота проверки угроз, ремонта, распределения рабочих и все приказы сохранены. Изменены только измерения и диагностический вывод. Устранение задержки пока не подтверждено.

Имеющийся BOSS::Timer использует QueryPerformanceCounter на Windows: это прошедшее время, которое может включать паузу планировщика ОС. По одному скриншоту нельзя отличить дорогой расчёт от внешней паузы процесса.

Проверены точки сброса/сохранения, порядок операций, структура исходников и git diff --check. Сборка, компиляция и игровой запуск не выполнялись по просьбе пользователя.
