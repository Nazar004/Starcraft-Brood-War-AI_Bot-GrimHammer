# Hannibal: пик при проверке расширения

Источник: присланный скриншот `codex-clipboard-02fc97f1-e678-4463-a428-0cdade8cb61c.png`.

- Текущий кадр 27337, среднее 3,7 мс.
- Сохранённый пик: кадр 18013, всего 83,0 мс.
- Production 69,2 мс; urgent expansion check 68,8 мс.
- Подготовка Combat 0,7 мс; обработка отрядов 7,8 мс.
- За пиковый кадр: maps 27, all 27, dist 27, move 0, place 0, evict 0, A* 1.
- Это другой пик и другой этап, чем Combat 258,5 мс на Andromeda.

## Код

`StrategyManager::handleUrgentProductionIssues()` в этапе expansion check вызывает `MapTools::getNextExpansion()`. Тот вызывает `nextExpansion()` и обновление оценок безопасности `refreshExpansionSafetyScores()`.

Оценка безопасности перебирает нейтральные базы и запрашивает расстояния от наших баз и базы противника до каждого кандидата. `getGroundTileDistance()` сначала ищет поле назначения, затем симметричное поле исходной точки; если ни одного нет — строит новое поле назначения. Старые вызовы передавали кандидата назначением. При холодном кэше это давало отдельное полное поле для каждого кандидата. Это подтверждённый источник лишних пересчётов в показанном медленном этапе; без дополнительного профиля нельзя приписать ему все 68,8 мс.

## Исправление

В двух вызовах `refreshExpansionSafetyScores()` переставлены аргументы: кандидат теперь исходная точка, фиксированная наша база / база противника — назначение. API уже использует симметрию наземных расстояний, а заблокированные точки нормализуются до обоих поисков кэша. Координаты концов маршрута и значения расстояний сохраняются; меняется выбор поля для заполнения кэша.

На холодном кэше запросы теперь строят общие поля для фиксированных баз и используют их для остальных кандидатов. Число необходимых полей в этом цикле ограничено количеством участвующих наших баз плюс база противника, вместо количества кандидатов. Кэш маршрутов A*, оценка опасности пути, проверка свободного рабочего, ресурсов, занятости и резервирования базы сохранены.

Изменён только `Map/MapTools.cpp`. Правила стратегии и частота проверки расширения сохранены.

## Проверка

Проверена цепочка вызовов, нормализация точек и симметричный поиск в существующем API. `git diff --check` выполнен. Сборка, компиляция и запуск игры не выполнялись по просьбе пользователя. Фактическое уменьшение времени кадра пока не измерено.
