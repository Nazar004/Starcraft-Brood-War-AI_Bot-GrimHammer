## Изменение WorkerManager

Раньше каждый подходящий минерал/газовый рабочий создавал составной BWAPI UnitFilter и вызывал общий getClosestUnit. Теперь тот же предикат создаётся один раз; подходящие враги собираются из getAllUnits один раз при каждом updateWorkerStatus. Проверки самообороны и опасности продолжаются каждый кадр.

При пустом списке целей возвращается nullptr. При непустом списке сначала проверяется наличие подходящего врага с getDistance(worker->getPosition()) <= 64. Если такой есть, вызывается прежний getClosestUnit с тем же предикатом и радиусом, сохраняя выбор цели и разрешение равных расстояний. Если нет, исходный запрос также не мог бы вернуть цель: в локальном BWAPILIB/Source/Game.cpp используется точно это необходимое условие радиуса. Проверено также, что BWAPIClient/Source/GameImpl.cpp применяет переданный предикат при поиске в прямоугольнике.

Список пересобирается при каждом вызове updateWorkerStatus, включая прямые вызовы, и не переносит сведения между кадрами или играми. Время сборки входит в defense. Проверка наличия ресурса и расстояния < 200 перенесена перед поиском цели: при невыполненном условии рабочий и раньше не получал приказ атаки.

Это устраняет заведомо пустые общие запросы, но не доказывает устранение всего пика 310,8 мс. Подтверждение ускорения требует следующего игрового прогона пользователя.

## Следующий замер плана

Добавлены этапы getTerranBuildOrderGoal: plan identity, threats, economy, composition, shared support, vessel tech, vehicle upgrades, expansion finish, normalize. Таймер включает оба возврата. Новая строка plan сохраняется на том же глобальном пике и показывается при пересчёте >= 5 мс. Частота и решения стратегии не изменены.

## Исправление вылета при запуске

После первой оптимизации пользователь сообщил о вылетах сразу при запуске. Прочитан актуальный bwapi-data/write/GrimHammer_CrashLog.txt: 2026-10-11 21:42:38, Circuit Breaker, кадр 0, callback onFrame, checkpoint WorkerManager::update, сообщение bad function call. Сырая часть стека содержит std::_Func_impl_no_alloc с lambda и BWAPI::Filter::HP. Это подтверждает связь вылета с новым фильтром рабочих.

Причина ошибки в первой версии правки: локальные заголовки BWAPI UnaryFilter.h и ComparisonFilter.h используют лямбды [=], которые в методах этих классов сохраняют указатель this. Составная цепочка фильтров содержит ссылки на временные левые операнды. В исходном прямом вызове getClosestUnit временные объекты живут до окончания запроса. В добавленном static UnitFilter они уничтожались после инициализации, а фильтр вызывался позднее уже с недействительными ссылками.

Составная цепочка заменена isWorkerDefenseTarget — обычной функцией. Сохранённый UnitFilter содержит только указатель на эту функцию и не захватывает временные фильтры или объекты игры. Критерии: враг, наземный, стоит или застрял, обнаружен, HP <= 35, не неуязвим и не spell. Добавлены проверки unit/exists, BroodwarPtr, self и owner. Оптимизация списка целей на кадр и исходный ближайший поиск при наличии подходящей цели сохранены.

В Source других сохранённых UnitFilter по поиску деклараций не найдено. Проверены критерии нового предиката, отсутствие составных BWAPI::Filter и захватов в его сохранённом объекте, структура WorkerManager.cpp и git diff --check. Причина дефекта исправлена в исходнике; запуск новой DLL ещё не проверен. Сборка, компиляция и игра не запускались по указанию пользователя.
